# Руководство по развёртыванию (администратор)

Версия соответствует 0.01.09. Требования к развёртыванию — раздел 10 ТЗ v0.01.01 (базовый образ node:22-alpine — решение D18).

## 1. Варианты развёртывания и выбор

| Вариант | Назначение | Требования | Ограничения |
| --- | --- | --- | --- |
| В1. Статические файлы (`out/`) на готовом веб-сервере или CDN | публикация студентам без Docker | доступ к каталогу публикации | базовый путь задаётся при сборке (`BASE_PATH`), пересборка при смене |
| В2. Локальный запуск разработчика | разработка и отладка | Node.js 22.12+ (22 LTS или 24), npm | не для эксплуатации; порт `PORT`, по умолчанию 3000 |
| В3. Локально в Docker | учебный класс, демонстрации, приёмка | Docker Engine 24+ (или Podman 4+) | порт 8080 |
| В4. Веб-сервер организации за обратным прокси | интеграция в портал вуза в подпапке | nginx/Apache с прокси-правилами | согласование конфигурации, `BASE_PATH` |

Приложение не имеет серверной части: тома, базы данных и служебные контейнеры
не требуются. Состояние пользователя живёт в localStorage браузера и привязано
к origin: при смене адреса публикации автосохранённые проекты не переносятся —
пользователь открывает сданный `state.yaml` через «Открыть состояние…».

Публикация каталога `out/` на бесплатном статическом хостинге GitHub Pages
(и другие бесплатные альтернативы, доступные из России) описана отдельно:
`docs/github-pages.md`.

## 2. Docker: сборка, запуск, остановка, healthcheck, обновление

```bash
make docker-build           # сборка образа skib-lab:0.01.02
make docker-run             # запуск на переднем плане, порт 8080
make docker-start           # запуск в фоне (контейнер skib-lab)
curl http://localhost:8080/healthz   # → 200 ok
make docker-logs            # логи
make docker-stop            # остановка и удаление
```

Свойства образа (раздел 10.2): многоэтапная сборка `node:22-alpine` →
`nginx:1.27-alpine` (node 22, а не 20 — требование `engines` vitest 5 из
devDependencies: на node 20 сборка выводит предупреждения `npm warn EBADENGINE`);
копирование `out/`; непривилегированный nginx (pid и tmp в /tmp);
`HEALTHCHECK` через wget; заголовки безопасности (CSP, nosniff, DENY, no-referrer);
кэширование `/_next/static/` — immutable, `index.html` — no-cache. Podman:
`make docker-build DOCKER=podman`.

**Если `npm ci` в сборке образа падает с «Exit handler never called!»** — это
известная ошибка npm при обрыве загрузки пакетов (нестабильная сеть, прокси,
нехватка памяти у Docker). Dockerfile устраняет её сам: до 8–12 повторных
попыток с длинными таймаутами, не более 4 одновременных соединений,
кэш npm сохраняется между сборками (BuildKit), при сбое выполняется резервная
попытка с двумя соединениями. Просто повторите `make docker-build` — уже
скачанные пакеты не качаются заново. Если не помогает: соберите на
Debian-варианте `make docker-build NODE_IMAGE=node:22-slim` и проверьте
память Docker (Settings → Resources, от 4 ГБ).

**Обновление**: собрать образ с новым тегом из `CHANGELOG.md`
(`make docker-build TAG=1.x.y`), остановить старый контейнер (`docker-stop`),
запустить новый (`docker-start`). **Откат**: запустить образ предыдущего тега.
Миграций нет; `state.yaml` совместим в пределах `version: 1`.

## 3. Makefile: цели и переменные

Цели: `help` (по умолчанию), `install`, `dev`, `build`, `preview`, `lint`,
`test-unit`, `test-unit-coverage`, `test-e2e`, `test`, `check`, `docker-build`,
`docker-run`, `docker-start`, `docker-stop`, `docker-logs`, `docker-shell`,
`clean`, `distclean`. Переменные: `DOCKER ?= docker`, `IMAGE ?= skib-lab`,
`TAG ?= 0.01.02`, `PORT ?= 8080` (порт хоста для `docker-run`/`docker-start`; внутри
контейнера nginx всегда слушает 8080), `BASE_PATH ?= /`. Порт dev-сервера задаётся
переменной окружения `PORT` в скрипте `npm run dev` (по умолчанию 3000):
`PORT=4000 make dev` — make передаёт переменные окружения в рецепты без изменений;
та же переменная согласует порт в `preview` (по умолчанию 4173) и в E2E-прогонах
(конфигурация Playwright наследует `PORT`). Цели `docker-*` проверяют
доступность рантайма и выводят понятную инструкцию; цели тестирования Docker
не требуют. Переменная `NODE_IMAGE ?= node:22-alpine` задаёт базовый образ
этапа сборки (запасной вариант — `node:22-slim`).

## 4. Публикация в подпапке (В1, В4)

```bash
BASE_PATH=/skib make docker-build TAG=0.01.02    # путь внутри портала
```

Пример nginx-конфигурации для В1 (копирование файлов):

```nginx
location /skib/ {
    alias /srv/skib/out/;
    try_files $uri $uri/ /skib/index.html;
    add_header Cache-Control "no-cache";
}
location /skib/assets/ { alias /srv/skib/out/assets/; add_header Cache-Control "public, max-age=31536000, immutable"; }
```

Для В4 проксируйте на контейнер: `proxy_pass http://127.0.0.1:8080;` при сборке
с тем же `BASE_PATH`, что и внешний префикс.

## 5. Чек-лист проверки после развёртывания (10.6)

1. `curl http://localhost:8080/healthz` → `200 ok`.
2. Страница открывается в браузере без ошибок в консоли.
3. Кнопка «Демо-проект» загружает комплект; `C_системы = 12` (контрольный пример 14.3).
4. После перезагрузки страницы состояние восстанавливается.
5. Экспорт `state.yaml` скачивается и повторно импортируется без ошибок (Э-08).

## 6. Диагностика типовых проблем

| Проблема | Причина и решение |
| --- | --- |
| Порт занят | освободите 8080 или запустите `make docker-start PORT=8081` |
| Статика грузится, но пути 404 | `BASE_PATH` при сборке не совпадает с адресом публикации — пересоберите с нужным значением |
| Пользователь видит старую версию | кэш `index.html`: проверьте заголовок `no-cache` в nginx.conf; обновите с Ctrl+F5 |
| «Проект пропал» после смены адреса | localStorage привязан к origin (раздел 10.1) — откройте `state.yaml` через «Открыть состояние…» |
| Контейнер не стартует | `make docker-logs`; проверьте, что порт 8080 внутри контейнера свободен и nginx.conf на месте |

## 7. Требования к среде и известные ограничения

- Docker Engine 24+ / Podman 4+ для В3; Node.js 22.12+ только для сборки (В1/В2);
  требование зафиксировано полем `engines` в package.json и файлом `.nvmrc`.
- Ограничение localStorage (~5 МБ на origin) —projects больших курсов храните
  файлами `state.yaml`.
- Сборка образа требует доступа к сети для базовых образов и npm-пакетов
  (раздел 10.2); исполняемый образ работает без сети.
