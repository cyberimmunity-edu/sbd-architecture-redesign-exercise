## 1. Текущее состояние (0.03.01b)

Реализовано и покрыто тестами (unit + E2E, гейт `make check`):

- **ДАП**: домены, внешние системы, стрелки с трассировкой обходов, периметр,
  автолейаут, undo/redo, лимиты Ф-17, валидация E-1xx…E-4xx.
- **ДВБ-аналитика**: уровни доверия (НДБ/ДДБ/ДДБПЦД), раскраска, «Расширенный анализ»,
  цели/функции/предположения, проверка диаграммы (E-501/E-502/W-006).
- **Модель стоимости**: C_домена = C_блока × S × M × K (K: 0.1/5/10), C_системы,
  контрольные примеры robot 486 / vessel 943.
- **ЛГ на ДАП** (v0.02.03): создание, вложенность, свёртывание, drag in/out,
  мультивыбор, цвета вне красного/жёлтого/зелёного; перемещение ЛГ целиком и
  ограничение периметра (v0.02.03b, Ф-78).
- **ДП** (v0.02.01): независимый парсер PlantUML (round-trip), валидация
  E-601…E-609 / W-007…W-009, лимиты Ф-58.
- **Советчик** (v0.03.01b): каталог С1–С9 с точной оценкой экономики (deltaC через
  пересчёт кандидата); С1 больше не предлагает декомпозицию интерфейсного домена
  из одних критичных функций (отзыв тестирования); **вариантный перебор разбиений**
  доверенных доменов — до трёх лучших вариантов на домен по точной deltaC:
  «валидатор + исполнитель» (trusted-split), «шлюз с функциями» (gateway-split),
  вынос некритичных (С1/С2); допущения посредника (С3) раскрыты в params;
  W-013 — обоснование forceTrusted при красном входе; тесты экономики на
  примерах репозитория и честной фикстуре пользователя (C = 335 = база
  сводного отчёта анализатора).
- **Интеграция с ИИ-агентами, топ-5** (v0.03.01): CLI `skib` (validate/check/metrics/
  advice/export/schema/version, JSON + fix_hint, коды возврата), таблица подсказок
  `HINTS` для всех кодов реестра, JSON-схема `docs/state.schema.json` (согласована
  с движком тестами), метрики `computeMetrics` (бюджет ДВБ), справочник
  `docs/ai-integration.md`.
- **CLI-гейты** (v0.03.01b): смоук `make cli` (486/943) и интеграционные
  CLI-тесты `make test-cli` (`tests/cli/run.mjs`, 16 проверок) в составе
  `make check`; правила проекта — `AGENTS.md` (отчёты только md, отказ от docx).

## 2. Принципы развития

1. **Транспорт-агностичное ядро.** Вся логика — чистые функции `src/engine` и `src/io`;
   GUI, CLI, MCP и будущие REST — тонкие адаптеры над одним набором портов
   (validate / export / import / metrics / advice / diff / layout). Новый транспорт
   не должен требовать изменений в ядре.
2. **Человек-в-цикле.** Агенты генерируют и считают, движок детерминированно
   проверяет, архитектор решает и утверждает (PR-процесс). Автоприменение
   архитектурных перестроений не вводится.
3. **Модель-в-коде, git — шина интеграции.** state.yaml хранится в репозитории;
   аутентификация, история, ревью и гейты — средства git-хостинга, а не инструмента.
4. **Офлайн и закрытые контуры.** Клиентские вычисления достаточны (лимиты модели
   малы); серверные компоненты — только по сработавшим триггерам (§5).

## 3. Ряд P0 — ближайший релиз (0.03.x)

| Задача | Обоснование | Оценка |
|---|---|---|
| **MCP-сервер (stdio)** — tools `validate_model`, `check_model`, `metrics`, `advice`, `export_model`, `load_sample` как обёртки над портами ядра | Стандарт подключения инструментов к агентским средам; CLI уже даёт всю функциональность | S (дни) |
| **Патч-формат операций** (`applyPatch`: add/move/remove/link/group) + `diff(a, b)` | Читаемые диффы в PR, совпадение с семантикой undo/redo (составная операция — один шаг истории) | M |
| **Канонический JSON-дамп** (`state.json`, `export --format json`) и стабилизация порядка сериализации | LLM устойчивее генерируют JSON; YAML остаётся проекцией для человека | S |
| **`skib layout`** — автолейаут в CLI (движок `computeAutoLayout` уже есть) | Агент правит структуру, координаты считает движок | S |
| **Панель «Бюджет ДВБ» в GUI** — отображение `computeMetrics` (size, costPercent, boundaryEdges) | Сделать экономику видимой архитектору в его рабочем месте | M |

Критерий готовности ряда: агент (внешняя LLM-среда) проходит сценарий «загрузить →
изменить → validate → metrics → предложить варианты» без ручных шагов.

## 4. Ряд P1 — развитие (0.04–0.05)

- **Вариантный синтез** — база готова и частично реализована в 0.03.01b
  (перебор разбиений одного домена с точной deltaC, топ-3). Дальше:
  генерация N кандидатов перестроения (генерация — внешняя LLM, перебор —
  движок), ранжирование по метрикам и deltaC на уровне всей модели
  (комбинации советов), сравнение двух state.yaml (`skib diff`) с отчётом
  «вариант / размер ДВБ / переходы / оценка».
- **Стоимостная надстройка с калибровкой**: конфиг весов (человеко-дни на доверенный
  домен, интерфейс, переход уровня) поверх метрик; калибровка по ретроспективе
  проектов. Веса — для ранжирования вариантов, не для публичных обещаний.
- **Экспорт контрактов модулей**: для каждой ДБ — роль, уровень доверия,
  разрешённые связи, последовательности из ДП; выдаётся агентам разработки.
- **Гейт «код ↔ модель» в CI**: адаптер (вне ядра) сверяет код модулей с
  контрактами; ловит расползание доверенной зоны при развитии системы.
- **Conformance suite round-trip**: в `make check` — проверка
  import(export(x)) == x на всех примерах и фикстурах.

## 5. Ряд P2 — серверные компоненты (v2, только по триггерам)

Серверные компоненты строить **при срабатывании триггера**, не раньше:

| Триггер | Решение | Что это |
|---|---|---|
| Совместное редактирование одной модели в реальном времени | sync-сервис (CRDT/блокировки) | Единственная задача, которую git-процесс решает плохо |
| Центральный реестр моделей, портфельная аналитика по десяткам систем | registry-сервис или пакетный сбор по репозиториям | Сначала попробовать пакетный сбор без сервиса |
| Remote-агенты (вне локальной машины) | **MCP over HTTP**, а не собственный REST | Тот же протокол, что и локально; без нового API-контракта |
| Интеграция с корпоративными ALM/СУД | REST-адаптер поверх портов ядра | Минимальный stateless-адаптер, не CRUD-зеркало модели |

Чего сознательно не делать: управление GUI агентами (puppeteer по канве);
REST до срабатывания триггеров; серверные вычисления (модель мала по лимитам).
Сохранение возможности v2 обеспечивается принципом §2.1 — при чистом ядре
каждый следующий транспорт — дни работы адаптера, а не переписывание.

## 6. Не забыть при каждом релизе

1. Версия в трёх местах: `package.json`, `APP_VERSION` (`src/engine/types.ts`),
   `TAG` (`Makefile`) — тест `makefile.test.ts` и CLI-смоук ловят рассинхрон.
2. `CHANGELOG.md` — запись с секциями Добавлено/Изменено/Исправлено.
3. `docs/ai-integration.md` и `README.md` — актуализация при изменении CLI/схемы;
   правила проекта — `AGENTS.md` (отчёты только md, контрольные числа).
4. Контрольные числа примеров 486/943 и честной фикстуры 335 не меняются
   (тесты + `make cli` + `make test-cli`).
5. `grep сложност src/` = 0 (термин не используется в коде и интерфейсе).
6. Сборка поставки: `make check` → `make zip` → обновление `download/README.md`,
   удаление устаревших артефактов из `download/` (отчёты — только md).
